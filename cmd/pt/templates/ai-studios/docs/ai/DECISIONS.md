# 設計決定與設計變更請求

實作時發現必須改變玩法規則、故事設定、謎題解答、玩家看得到的行為、玩聚架構或宣告的遊戲伺服器架構時，在這裡新增一筆，**不要直接改設計文件或程式**。開發者決定後把狀態改成 `accepted` 或 `rejected`，再更新 `design/` 與程式。不影響玩家體驗的實作細節不需要記錄。

格式：

```
## <日期> <短標題>（狀態：open）

DESIGN_CHANGE_REQUEST
Current Design:
Problem:
Proposed Change:
Player-facing Impact:
Technical Impact:
Alternatives:
Recommendation:
```
